# Сценарий защиты

## Что сказать в начале

«Вариант 3. Реализован пошаговый верификатор доказательств на Python.
Базовые операции — отрицание и дизъюнкция. Семь аксиом взяты из таблицы
задания. Импликация раскрывается в отрицание антецедента и дизъюнкцию
с консеквентом. Программа проверяет синтаксис, MP и одну равномерную
подстановку за шаг. Все успешно принятые строки сохраняются в сеансе».

## Демонстрация примерно на пять минут

1. Запустить `py -3 lab1.py`. Показать семь аксиом.
2. Ввести `mn -> (p -> p)` и `p -> (p -> p))`. Показать ошибки и `:list`:
   ошибочных строк в доказательстве нет.
3. Ввести `:tree p -> q`. Показать OR, NOT, p, q. Объяснить, что это
   дерево `~p | q`, а не строковое сравнение.
4. Ввести `a -> (a | b)`. Получить отказ: нужны две замены в A1.
5. Ввести `a -> (a | q)`, затем `a -> (a | b)`. Оба шага приняты
   отдельными β. Сообщения показывают p↦a и q↦b.
6. Ввести `:reset` и последовательно семь строк из `examples/demo.txt`
   без комментариев. На третьей и шестой строках показать MP со ссылками
   на обе посылки, на пятой — вставку составной формулы.
7. Ввести `:list`. Затем `p`: отвергнуто, хотя A1 содержит p как часть
   доказанной импликации. Подформула не становится доказанной автоматически.
8. Ввести `:quit`, выполнить `py -3 -m unittest discover -s tests -v`.
   При необходимости показать `evidence/tests_python314.txt`.

## Обоснование каждой строки демонстрации

| Строка | Формула | Основание |
|---|---|---|
| 1 | `~q -> ~q` | β из A7, p↦~q |
| 2 | `(~q -> ~q) -> (q -> q)` | β из A6, p↦q |
| 3 | `q -> q` | MP из 2 и 1 |
| 4 | `p -> (p | r)` | β из A1, q↦r |
| 5 | `(q -> q) -> ((q -> q) | r)` | β из 4, p↦(q→q) |
| 6 | `(q -> q) | r` | MP из 5 и 3 |
| 7 | `(q -> q) | (s | ~s)` | β из 6, r↦(s∨¬s) |

Третью строку также можно получить одним β из A7. Проверяющий алгоритм
сначала ищет MP, поэтому в этом сеансе показывает имеющееся обоснование MP.
Это не меняет логическую корректность. В варианте 3 `p -> p` само
совпадает с A7 после раскрытия сокращения.

## Вопросы и ответы

**Почему не таблицы истинности?** Задание требует проверки шагов доказательства.
Тавтология может требовать нескольких шагов, которых пользователь еще не ввел.
Булевы оценки используются только в независимых тестах аксиом и демонстрации.

**Как работает β?** Для каждой переменной исходного дерева сопоставляются
узлы источника и результата. На каждом месте этой переменной требуется одно
и то же поддерево. Остальные переменные и все операции должны совпадать.
Если нашли такую вставку, сохраняем переменную, дерево и источник.

**Чем подстановка отличается от изменения одного узла?** Заменяются все
вхождения выбранной переменной. Из `p -> (p | q)` нельзя получить
`a -> (p | q)` заменой только первого p.

**Можно ли подставить p|q вместо p?** Да. Вставленное выражение не подвергается
той же подстановке повторно, поэтому операция конечна.

**Почему аксиомы не схемы?** Наличие отдельного β и требование одной замены
за шаг означают, что произвольный экземпляр с несколькими заменами нельзя
заранее принимать как исходную аксиому. Пример методички тоже выводит
экземпляры K/S отдельными β.

**Почему импликация группируется слева?** Это прямо указано в лекции 1,
слайд 16, и используется в семинарских решениях. В выводе печатаются
полные скобки, поэтому группировка не скрыта.

**Что значит отказ?** Нет основания для непосредственного следующего шага
в данном сеансе. Это не утверждение о недоказуемости во всей системе.

**Как гарантируется правильность MP?** Дерево A⊃B раскрывается в OR(NOT(A),B).
В базе обязательно должно находиться отдельное структурно равное A.
Получение A из B не реализуется, будущее доказательство не используется.

**Что происходит после ошибки?** Состояние не меняется. Номер следующей
успешной строки остается прежним. Файл продолжает проверяться.

**Что с пунктом 7 в задании?** Исходной A7 принята левая формула ¬p∨p.
Равенство — метазапись, не связка входного языка. Правая часть имеет другое
дерево после раскрытия импликации и не добавляется второй аксиомой.

**Что с неклассическими логиками?** Вторая лекция показывает Клини и
Лукасевича, но текущая ЛР требует конкретное исчисление выбранного варианта.
Трехзначный вычислитель не подменяет этот верификатор.
