# Лабораторная работа 2 Вариант 3

Интерпретатор классической логики, сильной логики Клини K3 и логики
Лукасевича L3. Вычисляет формулы, строит полные таблицы истинности,
проверяет семантические свойства и отношения следования.

## Запуск

Нужен **Python 3.10 или новее**. Программа и тесты используют только стандартную
библиотеку; `pip install` не требуется. Откройте терминал в этой папке:

```powershell
py -3 lab2.py
```

Можно открыть `start.cmd` двойным щелчком. Без аргументов появляется меню
с обоими сценариями задания; режим 6 показывает весь вариант 3. Если `py`
отсутствует, используйте `python`. В Linux/macOS используйте `python3`.

## Воспроизводимые команды

```powershell
py -3 lab2.py eval "p -> q" --logic k3 --values "p=1/2,q=1/2"
py -3 lab2.py eval "p -> q" --logic l3 --values "p=1/2,q=1/2"
py -3 lab2.py table "~(p | ~p)" --logic k3
py -3 lab2.py analyze "p | ~p" --logic classic
py -3 lab2.py compare "(p -> q) -> (~q -> ~p)"
py -3 lab2.py compare "p -> q" --values "p=1/2,q=1/2"
py -3 lab2.py entails --premise "p -> q" --premise "q -> p" --conclusion "p | ~p" --logic l3
py -3 lab2.py entails --premise "p" --premise "~p" --conclusion "q" --logic k3
py -3 lab2.py tree "~p -> (q & r)"
py -3 lab2.py variant
py -3 lab2.py variant --output output
```

Последняя команда сохраняет `output/results.json` и **27 полных CSV**:
15 таблиц пяти формул и 12 таблиц четырёх отношений. В таблицах отношений
есть значения каждой посылки, заключения и признаки совместной модели
и контрпримера. CSV имеют UTF-8 BOM и разделитель-запятую.

В подкомандах доступен `--json`. `compare --logics k3 l3` сравнивает
выбранные системы, `compare --no-table` скрывает таблицу. `entails --table`
показывает все строки; без `--premise` проверяется общезначимость заключения.
Список команд — `py -3 lab2.py --help`; справка команды — например,
`py -3 lab2.py entails --help`.

Код выхода `0` означает успешный расчёт, в том числе обнаруженное отсутствие
следования; `2` — ошибку синтаксиса, оценки, аргументов или файловой операции;
`130` — прерывание вычисления Ctrl+C. В меню ошибка не завершает сеанс.

## Синтаксис и значения

| Конструкция | Запись |
|---|---|
| Переменная | Одна латинская буква a–z или A–Z; регистр различается |
| Отрицание | `¬p`, `~p`, `!p` |
| Конъюнкция | `p ∧ q`, `p & q` |
| Дизъюнкция | `p ∨ q`, `p | q` |
| Импликация | `p → q`, `p ⊃ q`, `p -> q` |
| Группировка | Круглые скобки, включая лишние парные скобки |
| Оценка | `p=0,q=1/2,r=1`; допустимы также `0.5`, `F`, `U`, `T` |

Математические Unicode-буквы `𝑝` нормализуются в `p`. Приоритет связок:
**¬, ∧, ∨, →**. Бинарные операции группируются слева по лекции 1,
слайд 16: `p -> q -> r` означает `(p -> q) -> r`. Правую группировку
нужно задавать скобками. Операции сохраняются в дереве, без упрощений.

Буквы `f` и `t` — переменные. Константы, кванторы, эквивалентность,
λ-термы и многобуквенные имена в язык не включены. Числа вводятся в оценке,
а не вместо формулы. Все переменные формулы должны иметь значения;
повторные, лишние и пропущенные имена диагностируются.

## Семантика

В классической логике V={0,1}, в K3 и L3 V={0,1/2,1}. Выделено только **1**.

```text
¬a = 1 − a
a ∧ b = min(a,b)
a ∨ b = max(a,b)
a →K3 b = max(1−a,b)
a →L3 b = min(1,1−a+b)
```

Классическая импликация совпадает с этими определениями на {0,1}.
При a=b=1/2 импликация равна 1/2 в K3 и 1 в L3. Поэтому парсер
сохраняет импликацию отдельным узлом, в отличие от реализации ЛР1.
Внутри используются `fractions.Fraction`, без округлений.

Общезначимость — значение 1 во всех оценках. Выполнимость — наличие
хотя бы одной оценки со значением 1. Невыполнимость отличается от
тождественной ложности: `¬(p∨¬p)` в K3/L3 никогда не равна 1,
но при p=1/2 равна 1/2. Контрпример к общезначимости допускает 1/2.

Γ⊨B проверяется по всем оценкам объединения переменных: контрпример
требует **каждую посылку=1 и B≠1**. Если совместных моделей посылок нет,
программа отдельно сообщает о вакуозной истинности следования.

Сравнение свойств выполняется на собственной области каждой системы.
Значения сравниваются попарно на общих допустимых оценках. При строке
с 1/2 классическая логика показывает `н/д` (в JSON — `null`), а не
вычисляет недопустимую оценку. Совпадение значений на {0,1} не означает
совпадение общезначимости на разных областях.

## Готовый результат и структура

- `lab2.py`, `multilogic/` — точка входа, дерево, парсер, семантика, CLI и вариант.
- `tests/` — тесты, включая отдельный расчёт по буквальным таблицам операций.
- `examples/session.txt` — ввод готового интерактивного сеанса.
- `docs/MATERIALS_REVIEW.md` — подробный разбор всех 27 учебных файлов.
- `docs/MATERIALS_MANIFEST.json` — SHA-256, исходные и текущие пути материалов.
- `docs/REQUIREMENTS.md`, `docs/DEFENSE.md`, `docs/VALIDATION.md` — требования, защита, проверки.
- `output/RESULTS.md`, `output/results.json`, `output/tables/` — результаты и полные таблицы.
- `output/LR2_variant3.docx`, `output/LR2_variant3.pdf` — отчёт.
- `output/LR2_variant3.zip` — переносимый комплект для сдачи.
- `evidence/` — фактические протоколы, версии Python и контроль переноса.
- `materials/` — исходное задание ЛР2; общие лекции/семинары находятся уровнем выше.

R3 введено буквально по PDF: третья посылка **r→s**. Его ложность
уже в классической логике подтверждается p=0,q=1,r=s=t=u=0;
формулировка задания не исправляется на q→s.

## Проверка и пересборка

```powershell
py -3 -m unittest discover -s tests -v
py -3 tools/verify.py
py -3 lab2.py variant --output output
py -3 tools/build_results.py
```

`tools/verify.py` сохраняет журналы и машиночитаемый итог в `evidence/`.
Дополнительные инструменты подготовки отчёта отделены от приложения:
`tools/build_report.py` использует `python-docx`, `tools/export_report.ps1`
экспортирует PDF через Microsoft Word. Их зависимости не нужны для запуска
программы, тестов или расчётов. После проверки DOCX/PDF комплект собирается
командой `py -3 tools/package_submission.py`; она проверяет CRC, SHA-256,
извлечение, тесты и запуск извлечённой копии.

Пределы: 4096 символов, 511 узлов и глубина 80 на формулу; до 32 посылок;
до 6561 оценки на полный перебор. При превышении выдаётся ошибка,
частичный перебор не объявляется полным. Для одной заданной оценки
экспоненциальный перебор не требуется.
